Decisioning and lending

01Lendflowdecisioning

A lending workspace. Applicant name with status chips, a chevron rail from Application through Underwriting to Funded, and an "orchestration run" card that groups each check (KYB, KYC, credit) with the providers it called.

Borrow: the chevron stage rail as the default pipeline view instead of a timing waterfall, and a per-check card that names the data source behind each rule.

lendflow.com
Alink only, no capture on file
02Alloydecisioning

Identity and credit decisioning for banks. An application queue with a review screen that leads with the outcome and the rule that produced it, then the evidence underneath.

Borrow: a one-line decision summary banner at the top of an applicant ("Declined by 4 of 5 lenders, best offer 15.9% from Northstar") before any card or chart.

alloy.com
Slink only, no capture on file
03Sardinedecisioning

Fraud and compliance ops. An alert table with a "Make decision" action and a bulk-decision modal that asks for a rationale once and applies it to every selected row.

Borrow: multi-select in the queue with one bulk approve or decline and a single rationale field, for clearing a stack of clean approvals fast.

sardine.ai
04Methoddecisioning

Liability data API. Entity pages with a big name, a mono id and an "Active" pill, then a two-column key/value overview and tables that use hairlines only, no card chrome.

Borrow: the no-chrome overview for the inspector snapshot, and status pills with a 6px dot for lender states so color carries meaning at a glance.

methodfi.com
05Evidencedecisioning

Reports that read like documents: sans headings, serif body, inline numbers, an "On this page" rail, and grey commentary blocks with a left rule.

Borrow: a reviewer commentary block on the adverse-action notice where the loan officer's note is stored next to the text they approved.

evidence.dev

Fintech ops

Mlink only, no capture on file
06Mercuryfintech ops

Business banking. A transaction list where clicking a row slides open a detail panel on the right, so the list never leaves the screen. Colour is used only for state.

Borrow: the list-plus-side-panel rhythm: keep the queue visible while the inspector opens, and never use colour for decoration.

mercury.com
Rlink only, no capture on file
07Rampfintech ops

Spend management. Approvals are exception-first: anything in policy clears on its own and only the exceptions reach a person, each with the policy line it broke.

Borrow: an "exceptions only" filter on the queue that hides applicants every lender agreed on, so the officer looks at split decisions first.

ramp.com
08Feyfintech ops

Markets app. A hero value with the cents dimmed, 38px rows with hairline separators, numbers right-aligned in tabular figures, and small green or red pills for change.

Borrow: group subtotal rows for the queue (approved today, declined today, dollars offered) and a delta pill on every offer against the best rate.

fey.com (archived)
09Hyperexpensefintech ops

Finance dashboard. Stat tiles with a large value and a "vs last month" pill, a policy-compliance arc gauge built from ticks, and horizontal tick-bar meters for percentages.

Borrow: one arc gauge for "reasons verified" on the eval panel, and tick meters for utilization and fraud score (the inspector already uses a version of this).

hyperexpense.com
10Finaryfintech ops

Wealth tracker. A single huge number, a timeframe control (1D, 1W, 1M), and an allocation list where every row is a label, a barcode-style bar and a percentage.

Borrow: a lender share bar: what fraction of today's approvals each lender won, as one barcode row per lender above the queue.

finary.com
11Lightyearfintech ops

Investing app. A light three-column home with the account value first, holdings in the middle, and a quiet right column for actions. Nothing competes with the number.

Borrow: the light-theme palette for the console's light mode, and the rule that one number per screen gets the large size.

lightyear.com
12Cobaltfintech ops

Property finance. A four-tile insight row across the top, then detail. The tiles answer "is everything fine" before the user reads anything else.

Borrow: a four-tile desk summary (waiting on you, decided today, median time to decision, dollars approved) as the first thing on the console.

joincobalt.com
Slink only, no capture on file
13Stripe Dashboardfintech ops

The reference for tabular figures and state-only colour. Ids are mono with a hover-to-copy affordance; every status is a muted pill; the page has almost no borders.

Borrow: copy-on-hover for applicant and offer ids, and dropping every decorative border in the inspector.

stripe.com

Traces and eval

14Respantraces and eval

LLM observability. Five KPI tiles with a coloured tick, a big mono number, a delta and a 24-bar sparkline, over a log table with sum and average rows. Its trace waterfall is what Docket's pipeline view copies.

Borrow: the KPI tile with sparkline for lender latency and approval rate, and the sum/average sub-header on the audit table.

respan.ai
15Laminartraces and eval

Agent tracing. Three panes: nav, a traces table with a 3px status bar on the left of each row, and an inspector that opens with a "Failure Detector" card before the transcript. Docket's shell is modelled on it.

Borrow: the failure card pattern for every decline, with a category chip and one sentence, shown before the detail.

lmnr.ai
16Arize Phoenixtraces and eval

Eval tooling. Experiments compared side by side as A and B columns with a score chip and a progress bar, plus per-row stat strips (latency, tokens, cost).

Borrow: the A/B column layout for the dispute replay, so before and after sit side by side with the changed fields scored.

phoenix.arize.com
17Axiomtraces and eval

Log analytics. Query steps as pill chips and a results table where the count column has a translucent bar filling each cell from the right in proportion to its value.

Borrow: in-cell bars for the eval failures and the per-lender agreement table, so the biggest number is visible without reading.

axiom.co
18Dash0traces and eval

Observability. A latency heatmap over time with attribute chips beneath it, so a slow lender shows up as a dark band rather than a number in a table.

Borrow: a lender latency heatmap on the eval tab, one row per lender across the 20 personas.

dash0.com

Shell and queue

Llink only, no capture on file
19Linearshell and queue

Issue tracking. The Triage inbox: one item at a time, numbered keyboard actions, a command palette for everything else. Dense, dark-first, no chrome that does not earn its place.

Borrow: a command palette (Cmd+K) for jumping to an applicant or running eval, and a one-at-a-time "triage" mode that shows the top of the queue full-width with A and X as the only actions.

linear.app
20Opikshell and queue

LLM evaluation. A light three-pane trace view: spans on the left, the selected span's input and output in the middle, metadata on the right, with the selected row carried by a left accent only.

Borrow: the light-theme three-pane treatment for the Trace tab, where each lender's input and output is readable without opening the audit log.

comet.com/opik
